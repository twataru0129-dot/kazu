# かずあそび（仮）

数字そのものを使って遊ぶ、子ども向けの日本語算数 Web アプリです。
「勉強をさせる」のではなく、数を分けたり組み立てたりして工夫する面白さを中心にしています。
5歳でも自分で操作でき、学年が上がっても続けられるように、年齢や学年によるロックはありません。

- スマートフォン・タブレット中心（縦持ち）、PC のブラウザでも使えます
- アカウント登録・サーバー・広告・課金・外部の解析ツールはありません
- 記録は端末内（このブラウザの保存領域）にプロフィールごとに保存します

## 起動のしかた

Node.js 22 以上が必要です。

```bash
npm ci            # 依存パッケージのインストール
npm run dev       # 開発サーバー（http://localhost:5173）
npm run build     # 本番ビルド（dist/）
npm run preview   # ビルド結果の確認（http://localhost:4173）
```

チェック類：

```bash
npm run typecheck # 型チェック
npm run lint      # ESLint
npm test          # Vitest（問題生成の大量テスト・保存・画面操作）
npx playwright test   # E2E（ビルドしてプレビューサーバーで実行）
npm run check     # typecheck + lint + test + build
```

Playwright のブラウザが入っていない環境では `npx playwright install chromium` を一度実行してください
（すでに Chromium がある環境では `PW_CHROMIUM_PATH=/path/to/chrome` でも指定できます）。

## 遊び方（4つのモード）

ゲームや問題の文字・数字は、iPhone で長押ししても文字選択やコピーのメニューが出ないようにしています（名前などの入力欄と、保護者向けの情報は選べます）。

ホームに大きな4つの入口があります。右上の歯車は「おとなのメニュー」、⇄ はあそぶ人の切り替えです。右下にアプリの版（`v1.7.1 + ビルドID`）を小さく表示します。

| モード | 内容 |
|---|---|
| けいさん | 足し算・引き算・掛け算・割り算を暗算で。桁数・繰り上がり/繰り下がり（なし・あり・まぜる）・問題数（5/10/20/ずっと）を選べます。間違えても何度でも直せます。正解後に「ほかのかんがえかた」（10をつくる、位ごとに分ける など）を見られます。「マスけいさん」に切り替えると100マス計算（下記）。 |
| あそぶ | 31種類の数字あそび。4段階の難しさ（かんたん／ふつう／むずかしい／チャレンジ）。3段階のヒントつき（ヒントを使っても正解は正解）。31 すうじたんていだけは難しさが1つで、ヒントのかわりに「あそびかた」をいつでも見られる。30 魔法陣パズルの むずかしい・チャレンジは ヒントなし（たて・よこ・ななめの合計の表示はあり）。 |
| まなぶ | 掛け算・割り算の意味を「みる（説明アニメ）→ うごかす → れんしゅう」で。九九表もあります。順番は自由です。 |
| テスト | 演算と難しさ・問題数（5/10/20/30）を自分で決めて挑戦。テスト中はヒントなし、答え合わせは最後にまとめて。中断しても続きから再開できます。「前と同じ条件でテスト」も。 |

### 100マス計算（けいさん → マスけいさん）

表の左と上の数を「左 ○ 上」で計算して、交わるマスに答えを入れます（1枚の表は1種類の演算だけ）。

| 難しさ | 表 | 演算 |
|---|---|---|
| かんたん | 3×3（9マス） | たし算（答えは10まで） |
| ふつう | 5×5（25マス） | たし算・ひき算（20まで、ひき算はマイナスにならない） |
| むずかしい | 10×10（100マス） | たし算・ひき算・かけ算（九九） |
| チャレンジ | 10×10（100マス） | たし算・ひき算・かけ算（2けた×1けた）・わり算（必ず割り切れる。左は公倍数の倍数、上はその約数） |

- マスをタップ（矢印キー）で選び、2段の数字キー（テンキー）で入力、「つぎの マス」（Enter）で次の空きマスへ。「ひとつ もどる」「← けす」「ぜんぶ けす」
- 10×10 は押せる大きさのままスクロール（左と上の数は固定表示）。「ぜんたい」で縮小表示
- 全部入れたら「こたえあわせ」。正しいマスは緑と ○、ちがうマスは赤と ×。直してもう一度採点できる
- タイマー表示は初期 OFF（時間制限なし）。表示中の時間は、休憩中・画面を隠している間は数えない
- 途中保存あり（同じ表・入力から再開）。記録は表1枚を1回として、おとなのメニューの「100マス計算」に別に表示（ふつうの計算の正答率には混ぜない）。自己ベストは同じ条件・タイマー表示あり・初回の答え合わせで全問正解の記録どうしで比べる

## あそぶ じかん（保護者の時間制限）と あんしょうばんごう

- 初期設定は **時間制限なし** です。
- 「おとなのメニュー → 設定 → 遊ぶ時間」で、4桁の暗証番号（PIN）を2回入れて決めると、1回に遊べる時間（5〜60分・5分刻み、はじめの選択は30分）を設定できます。
- 時間は **アプリが表示されていて、子ども向けの画面にいる間だけ** 減ります（非表示・バックグラウンド・おとなのメニュー・ロック画面では減りません）。プロフィールを変えても、リロード・別のタブでも同じ残り時間です。
- 残り5分で「あと 5ふんで おしまいだよ」と1度だけ案内し、時間になると「おしまいの じかんだよ！」の画面になります。保護者が PIN を入れると解除され、時間は設定値に戻ります。解除直後や設定を保存した直後は、子どもがモードを選んで遊びはじめるまで数えません。
- PIN を決めると、おとなのメニューは長押しではなく PIN で開くようになります（長押しの入口は PIN 未設定のときだけ）。5回続けてまちがえると、30秒から待ち時間が入ります。
- PIN はそのまま保存せず、ランダムな salt と PBKDF2-SHA256 で作った検証用データだけを保存します。**PIN を忘れたときの秘密の解除方法はありません**（ブラウザのデータを消すと記録も消えます）。メモして安全な場所に保管してください。家庭向けの簡単な保護で、端末全体を守るものではありません。
- 時間制限・PIN・残り時間は、アプリ（この端末のこのブラウザ／ホーム画面アプリの保存領域）全体で1組です。学習記録のバックアップには含めず、バックアップの復元やプロフィールの追加・削除ではロックを解除できません。Safari とホーム画面アプリでは保存領域が分かれることがあるため、端末全体での制限は保証できません。

## 記録の保存とバックアップ

- 記録は **この端末の、このブラウザ（またはホーム画面アプリ）の保存領域** の IndexedDB に保存します。
  同じ端末でも Safari と Chrome、ブラウザとホーム画面アプリでは保存が別になることがあります。
- ブラウザのデータ削除、プライベートモード、容量不足、ブラウザによる自動削除などで消える可能性があります。
  IndexedDB が使えない環境では「保存できない」ことを画面に表示し、一時的に遊べるようにします（保存できたとは表示しません）。
- 「おとなのメニュー」→「バックアップ」で、すべてのプロフィール・設定・記録を JSON ファイルに書き出せます。
  復元時は中身の検証とプレビューを行い、「追加」か「すべて置き換え」を選べます。
  壊れたファイル・別のアプリのファイル・新しすぎる形式・ID の重複・持ち主のいない記録は読み込まず、
  復元は1つのトランザクションで行うため、途中で失敗しても今のデータはそのまま残ります。
- アプリの更新では記録は消えません（Service Worker とキャッシュの整理は IndexedDB に触れません）。

### アプリの自動更新

- 起動したとき・アプリに戻ってきたとき（iPhone のホーム画面アプリを含む）・オンラインに戻ったとき・30分ごとに、新しい版があるか確かめます。
- 新しい版が見つかったら、**ホーム・プロフィール選択・ゲーム一覧・まなぶの一覧** にいるときだけ自動で切り替え、1回だけ再読み込みします。
- 計算・ゲーム・テスト・まなびのレッスン・おとなのメニューの途中では切り替えません。これらの画面からホームや一覧に戻ったとき（または次に起動したとき）に切り替わります。保存中の書き込みが終わるのを待ってから再読み込みします。
- ページ本体はネットから取りに行き（3秒で返事がなければ手元の版）、オフラインのときは今の版でそのまま遊べます。
- 今の版はホームの右下（`v1.7.1 + commitの先頭7桁`）と「おとなのメニュー → 保存について → アプリの版」（`1.7.1+commitの先頭7桁`）で確認できます。GitHub Pages を更新すると、新しく公開したビルドの ID に変わります。

## 静的公開（GitHub Pages）

ビルドは相対パス（`base: './'`）とハッシュ方式のルーティングを使うので、
`https://<ユーザー名>.github.io/<リポジトリ名>/` のようなサブパスでもそのまま動きます。
絶対パスにしたい場合は `BASE_PATH=/kazu/ npm run build` のように指定できます。

公開の手順：

1. （はじめの1回だけ）GitHub のリポジトリで **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする
2. main に push する（PR をマージする）と、**Deploy to GitHub Pages** が自動で実行されます。型チェック・lint・テスト・ビルドがすべて成功したときだけ公開します。PR を作っただけでは公開されません
3. 手動で公開し直したいときは **Actions → Deploy to GitHub Pages → Run workflow** でも実行できます
4. 完了すると Pages の URL が表示されます。スマホで開き、「ホーム画面に追加」するとアプリのように使えます

`dist/` を任意の静的ホスティングに置くだけでも動きます。

## 技術構成

- React 19 + TypeScript + Vite（静的 SPA / PWA、自作の Service Worker）
- 保存：IndexedDB（自作の薄いラッパー、スキーマ版管理つき）。localStorage/sessionStorage は「最後に選んだ人」の記憶だけ
- 効果音：Web Audio で合成（音声ファイルなし）。読み上げ：ブラウザの Speech Synthesis（ある場合のみ、字幕は常に表示）
- 画像：すべて自作の SVG（動物アバター、硬貨・商品のイラスト、説明アニメ）
- テスト：Vitest + Testing Library + fake-indexeddb、Playwright
- 外部 API・トラッキング・CDN 読み込みなし（オフラインで動作）

```
    tests/        テストの採点・時間計測・集計
  games/          ゲーム共通の進行画面（GameScreen）と30ゲーム固有の画面（views/）。31 すうじたんていは専用画面（screens/NumberDetectiveScreen.tsx）
  persistence/    IndexedDB、リポジトリ、バックアップ
  screens/        ホーム・計算・まなび・テスト・おとなのメニュー

e2e/              Playwright

```

アプリ名・色は `app.config.json`・`src/config/theme.ts` で差し替えられます。

### アプリアイコン

- 採用デザインの原画は `assets/icon/` にあります（`kazu_app_icon_1024.png` がマスター、512・192・180px も同梱）。
- アプリで使うのは `public/icons/app-icon-192.png`・`app-icon-512.png`（manifest・ブラウザのタブ）と `app-icon-180.png`（iPhone/iPad のホーム画面）です。対応表は `app.config.json` の `icons`。
- 差し替えるときは `assets/icon/` の PNG を同じ大きさの新しい画像に置き換えてから `node scripts/make-icons.mjs` を実行します。
  このスクリプトは原画を `public/icons/` へ**コピーして大きさを確認するだけ**で、絵を描き直したり別の画像から書き出したりはしません（以前の SVG からの書き出しは廃止）。
- アイコンの中身が変わると Service Worker の版も変わるので、ホームの「こうしん する」で新しいアイコンのファイルに入れ替わります。

### iPhone のホーム画面のアイコンが古いままのとき

アプリ本体の更新では記録は消えませんが、iPhone のホーム画面に追加したアイコンの絵は、追加したときのものが残ることがあります。
「サイトデータをすべて消去」はしないでください（記録が消えます）。次の順で入れ替えてください。

1. ホーム画面のアプリを開き、「おとなのメニュー」→「バックアップ」で JSON を保存する（念のため）
2. Safari で公開ページを開き、ホームの「こうしん する」が出ていれば押す
3. ホーム画面に新しく「ホーム画面に追加」する（古いアイコンは、新しい方で記録が見えることを確認してから削除）
4. 新しい方で記録が見えないとき（ホーム画面アプリは保存領域が別のことがあります）は、手順1のファイルを「バックアップ」→「復元（追加）」で読み込む
